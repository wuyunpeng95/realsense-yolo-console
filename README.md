# DepthSight · D435i 深度视觉控制台

本机网页控制台，同时显示 RealSense D435i 的 RGB、近黑远白深度图，并用 YOLO11n 检测人员和估计轴向距离。所有采集和推理都在本机完成，画面不上传云端；启用飞书告警后仅向配置的机器人发送文字检测摘要。

## 启动

当前电脑已安装依赖，项目内已放置 `models/yolo11n.pt`。连接 USB 3 相机后，双击 `start.bat`，浏览器打开 **http://127.0.0.1:8000**。也可在项目目录运行：

```powershell
python app.py
```

保持启动进程运行。控制台中按 `Ctrl+C` 可退出并释放相机；网页的“停止采集”仅停止相机，服务继续运行。服务默认只监听本机，不需要 Node.js、前端编译或外部 CDN。

新电脑安装：建议先创建 Python 虚拟环境，再运行以下命令。需要具备对应 Python/Windows 版本的 RealSense SDK 和 PyTorch wheel。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python setup_model.py
python app.py
```

首次下载模型需要联网；之后可离线运行。模型来源是 Ultralytics 官方 assets 发布。YOLO 模型及 Ultralytics 软件适用其 [AGPL-3.0 / Enterprise 许可](https://www.ultralytics.com/license)，商业集成时应根据使用方式确认许可。

## 功能

- 640×480、30 FPS 设定采集；实际采集及处理帧率在网页显示。
- 深度通过 `rs.align(rs.stream.color)` 对齐至 RGB。前端同一消息展示一组 RGB、深度和检测结果，避免跨帧标注。
- YOLO11n COCO 预训练，仅推理 person / class 0，支持置信度和 320/480/640 输入尺寸调节。
- 人员框、置信度、当前人数、短时 IoU 编号、躯干有效深度占比和轴向距离。
- 可关闭人员检测并保留双画面；模型错误时也可继续看画面，提供模型重载入口。
- 深度范围实时调节、点击最新深度帧像素测距、相机启停、相机断线自动重连、WebSocket 自动重连。
- 导出同步快照 ZIP，以及当前浏览器会话运行记录与真实设备信息。参数为当前服务会话设置，服务重启恢复默认值。

## 算法与架构

```text
D435i → RealSense SDK / RGB + Z16
      → 深度对齐至 RGB → 采集线程 → 最新帧槽（不堆积旧帧）
      → 推理线程 / YOLO11n(person) + 躯干 ROI 稳健中位数测距
      → RGB JPEG + 灰度深度 PNG + JSON / 同一 WebSocket 二进制包
      → 原生 HTML/CSS/JavaScript / Canvas 叠加标注
```

CPU 默认最多使用 4 个 PyTorch 线程；若安装的 PyTorch 支持 CUDA 且存在可用 GPU，自动选择 CUDA。没有 GPU 时选择轻量 YOLO11n，不强制安装 CUDA 或 ONNX。采集与推理分离，推理较慢时丢弃未处理的旧帧，优先显示最新场景。

深度映射为 `1 + 254 × clip((距离 - near) / (far - near), 0, 1)`，无效测量保留为 0。近处接近黑色，远处白色；超出显示范围的有效深度分别截断到近黑/白端，不改变原始数据。固定范围避免逐帧自动归一化造成亮度漂移。纯黑也可能是无效测量，点击像素可区分。

测距使用框内横向 30%～70%、纵向 20%～65% 的躯干区域，滤除无效深度，对有效值做 IQR 异常值剔除后取中位数。有效像素不足 30 个或比例不足 35% 时不提供距离；IQR 较大时标记深度波动。距离表示相机光轴方向 Z 深度，非人体到相机的欧氏距离。IoU 编号仅是短时跟随，不是身份识别，遮挡、交叉移动或长时间离开可能更换编号。

**真人检测边界：** 当前为 person 目标检测与深度辅助测距，不是防照片、防屏幕翻拍或活体认证。照片、屏幕、假人仍可能被识别为 person；有有效深度并不等于通过真人验证。严格活体检测需要独立的反欺骗算法、数据集与验证流程。

## 飞书人员告警

默认规则：**同一人员连续出现在处理帧中超过 5 秒，且当前帧原始置信度严格大于 85%**，两个条件同时满足才触发。等于 5 秒或等于 85% 不触发，不按界面四舍五入后的数值判断。网页“飞书人员告警”中可调整连续出现时长（0.1～3600 秒）及推送置信度（10%～99%）；两者与冷却间隔一并保存，重启保留。检测配置中的置信度筛选仍会影响哪些目标进入人员跟随和告警判断。

每个人按当前短时跟随编号独立计时，使用采集帧的单调时钟，不会将不同人员的时间相加，也不会把多次离开再进入的时间累计。只要仍被检测为 person，出现时间可继续累计；只有推送时要求当前置信度超过推送阈值。任何一帧漏检、编号改变、采集停止、检测关闭、相机重连、超过 1 秒没有连续处理帧，都会重新开始计时；修改推送时长、置信度或启停自动告警也重新计时，旧规则尚未发送的消息会取消。快速移动、遮挡或漏检可能推迟告警。冷却和发送期间仍持续跟随计时。

同一采集会话中，**同一个编号在飞书确认发送成功后只告警一次**，冷却结束也不重复发送。漏检、置信度波动、修改规则或关闭再打开推送不会清除已通知编号。一次推送只汇总满足两个条件且尚未通知的新编号；已通知的人仍会保留在画面和人数统计中，不会夹带进下一批告警。新编号需要单独满足持续时长，且受全局冷却限制。发送失败不会标记为成功通知，仍可在冷却后重试；连接测试不占用任何人员编号的通知机会。

消息包含北京时间、设备名称、人数、最高置信度、各目标首次出现时间、连续出现时长、当前置信度、轴向距离、深度质量和帧编号。不发送图片，也不以“活体认证成功”表述检测结果。

在网页“飞书人员告警”的“飞书 Webhook 完整地址”输入框粘贴完整机器人地址，点击“保存推送地址”即刻生效，无需修改代码或重启。保存后输入框清空并显示“地址已配置”，不自动回显完整地址，留空不会覆盖原地址；可继续粘贴新地址替换，并点击“发送连接测试”检查通道。

地址写入本机 `config.local.json` 的 `feishu.webhook`，该文件已被 Git 忽略，不会在状态 API、快照或运行记录中返回完整地址；程序源码中没有实际机器人的固定地址。只接受完整的飞书自定义机器人 HTTPS 地址。网页保存的本地值优先使用，未配置本地字段时才使用可选的 `FEISHU_WEBHOOK` 环境变量作为默认值。如果机器人启用了签名校验，可通过 `FEISHU_SIGN_SECRET` 环境变量或本地 `feishu.sign_secret` 配置签名密钥。

修改为不同地址会取消旧地址尚未发送的消息，并为新地址重新计时、重新记录已通知编号；同一地址再次保存不会清除去重记录。已发出的网络请求可能仍在原地址完成，不会重定向到新地址。

默认自动告警开启、全局冷却 60 秒，冷却用于限制不同批次新目标告警的频率。网页可启停推送、修改 15～3600 秒冷却时间、发送连接测试和查看最近成功/失败状态；参数写回本地配置，重启保留。已通知编号、冷却状态与发送计数仅保留在当前服务进程内；重新采集、相机重连或服务重启会建立新的采集会话，编号可能重置，届时重新判断。当前为短时目标跟随，不具备跨编号或跨会话的人体身份识别。

发送使用独立后台线程和有界队列，单次网络超时 5 秒，失败最多尝试 3 次（间隔 2 秒、4 秒）；网络超时后重试可能造成重复消息。HTTP 200 但飞书 `code != 0` 仍按失败处理，网页会提示检查机器人关键词、签名或 IP 限制。连接测试明确标记为测试，不冒充人员检测告警，也不占用人员告警冷却周期。

接口：`PATCH /api/notifications` 修改 `webhook`（完整地址）、`enabled`、`cooldown_seconds`、`threshold`（0～1 概率，此接口允许 0.1～0.99）、`min_visible_seconds`；`POST /api/notifications/test` 加入连接测试队列。接口仍要求同源和 `X-Console-Request: 1`。推送状态和当前最长连续出现时间在 `/api/status` 的 `notifications` 中返回。

参考：[飞书自定义机器人官方指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

## 同步快照文件

- `rgb.jpg`：原始彩色帧。
- `rgb_annotated.jpg`：带人员框和英文标签的彩色帧。
- `depth.png`：8 位近黑远白显示图，不含画面标注。
- `raw_depth.png`：无损 16 位对齐深度；乘 `metadata.json` 中 `camera.depth_scale` 得到米，0 为无效值。
- `metadata.json`：帧序号、采集时间、SDK 双流时间戳、深度单位、RGB 内参、设置、检测框和距离。

浏览器点击测距读取服务端最新处理帧，并显示其帧序号；移动场景中它可能比点击瞬间浏览器显示的帧更新。快照内所有文件属于同一处理帧。

## 验证与排障

```powershell
python -m unittest discover -s tests -v
```

真实相机端到端检查（需先启动服务；会暂时修改参数并重启采集，结束时恢复设置）：

```powershell
python tests/hardware_check.py
```

- 相机异常：关闭 RealSense Viewer、其他相机程序，改用 USB 3 数据线或 USB 3 接口；后台每约 2 秒重试。沙箱运行环境可能限制驱动创建系统互斥量，应在普通本机进程运行。
- 网页服务重连：确认启动进程仍在运行、端口为 8000；不要直接双击 HTML 文件。
- 模型错误：确认 `models/yolo11n.pt` 存在，可运行 `python setup_model.py` 获取，再点击重新加载。
- CPU 帧率较低：改用 320 或 480 推理尺寸，观察处理 FPS；相机采集 FPS 和推理 FPS 独立。
- 弱光、反光、透明物体及遮挡可能造成深度空洞和测距波动，界面会显示深度质量。
